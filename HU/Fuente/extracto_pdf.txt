1. Introducción y Alcance del Sistema
El presente documento define los requerimientos funcionales y no funcionales detallados, junto con los
lineamientos de arquitectura para la construcción del sistema de gestión comercial y clínica de la óptica. El
objetivo  principal  es  centralizar  la  operación  del  negocio,  mitigando  errores  en  el  manejo  de  inventario
especializado de salud visual y optimizando el flujo de facturación.

3. Documento de Arquitectura y Guía de Desarrollo Técnico
Para garantizar la mantenibilidad, extensibilidad y un alto estándar de ingeniería, el software se diseñará bajo
los principios de  Clean Architecture (Arquitectura Cebolla) combinado con patrones de segregación de
responsabilidades de consultas y comandos  (CQRS). El frontend se implementará de manera nativa con
Blazor WebAssembly (.NET 10).
3.1. Estructura de la Solución
OpticaSolution/
├── src/
│   ├── 1. Core/
│   │   ├── Optica.Domain/
│   │   └── Optica.Application/
│   ├── 2. Infrastructure/
│   │   ├── Optica.Infrastructure/
│   │   └── Optica.Shared/
│   └── 3. Presentation/
│       ├── Optica.API/
│       └── Optica.Client.Blazor/
3.2. Arquitectura del Backend: CQRS con MediatR
Toda lógica de negocio en la capa de Application se dividirá estrictamente bajo el patrón CQRS utilizando la
librería MediatR.
3.3. Implementación del Frontend con Blazor WebAssembly
El proyecto aprovechará el modelo de ejecución del lado del cliente de Blazor, utilizando librerías como
MudBlazor para  la  UI  interactiva  y  contenedores  de  estado  en  memoria  para  la  gestión  del  POS  sin
recargas.
